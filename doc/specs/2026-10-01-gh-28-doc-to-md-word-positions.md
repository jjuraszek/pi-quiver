# doc_to_md word positions: per-page word boxes for text-layer and OCR words

**Goal:** Let a `doc_to_md` caller ask, per call, for the position of every word on each converted PDF or image page - native text-layer words and the words OCR recognized in the same run - as a JSON artifact beside the output the words belong to, without a second OCR pass, a settings key, or any change to the Markdown.

Supersedes [doc/specs/2026-09-30-gh-25-doc-to-md-bundle-gaps.md](./2026-09-30-gh-25-doc-to-md-bundle-gaps.md), the deferred `<stem>.words.json` acceptance criterion only (its JSON sketch becomes the format below). Supersedes [doc/specs/2026-10-01-gh-26-caller-driven-ocr-sidecars.md](./2026-10-01-gh-26-caller-driven-ocr-sidecars.md), the "Positional word sidecars" out-of-scope line only.

## Problem

A consumer that pairs values by geometry (an equipment tag with the rating printed next to it on a drawing) needs the box of every word on a page. The converter already holds that geometry: PyMuPDF's `page.get_text("words")` returns `(x0, y0, x1, y1, text, block, line, word)` for the text layer, and both OCR paths leave their recognized words reachable from the same page objects. Today the bundle throws the geometry away and ships only Markdown, so the consumer has to reopen the PDF and, for scanned pages, run OCR a second time.

Two facts about the engine shape the design (verified against pymupdf 1.27.2.3 and pymupdf4llm 1.27.2.3, the pinned backend; also verified: on `test/fixtures/multipage.pdf` page 1 `get_text("words")` returns 13 tokens equal to `get_text("text").split()` in order):

- The default `textless` OCR path (`pymupdf4llm.to_markdown(force_ocr=True)`) mutates the open document: it inserts the recognized text as spans with font `GlyphLessFont`, so one `page.get_text("words")` after conversion returns native and OCR words together, provenance readable from the span font. On `test/fixtures/scan.pdf` page 1 this yields `Hello OCR world 12345` with `Hello` at x0 = 54.2 pt inside the picture rect (36, 72, 576, 175).
- The `ocrMode: all` path (`mode_ocr_pages`, a second Python child) builds a transient `page.get_textpage_ocr(full=True)` and never touches the document; its words are reachable only inside that child via `page.get_text("words", textpage=tp)`. Full-page OCR does not mask native text: on `test/fixtures/short-text-ocr.pdf` page 2 the text layer holds `3` and the OCR textpage holds `3 Hello OCR world 12345`, so `all` recognizes native words a second time.

Coordinates: pymupdf4llm calls `page.remove_rotation()` on every page it converts, so a converted page reports `rotation == 0` and `get_text("words")` is already in display space. A page not converted by pymupdf4llm (fallback tier, the `ocr-pages` child) returns unrotated coordinates; `Rect(bbox) * page.rotation_matrix` maps them to display space (verified: `NORTH` inserted at (72, 72) on a `/Rotate 90` page maps to display x0 = 716.4, y0 = 72.0; `page.rect` is display-oriented in both states).

Ticket corrections: the ticket proposes a `quiver.docToMd.words` setting - the user decided `words` is per-call only; the ticket calls `Hello OCR world 12345` "five words" - the fixture text (`test/fixtures/generate.py`, `OCR_TEXT`) is four whitespace tokens; the ticket writes one file per page under `words/` - the user accepted one `<stem>.words.json` mirroring the Markdown plus `ocr/<stem>-pNNN.words.json` beside each forced-OCR sidecar, because `all` OCR runs in a different process and is deliberately kept apart from the trusted Markdown.

## Design

### 1. Option

`words` is a per-call boolean in `DOC_TO_MD_OPTIONS` (`lib/doc-to-md-options.ts`) with `flag: "--words"`, `settable: false`, default `false`, modeled on `pageImages`. It joins `PerCallInput` and `DocToMdOptions`, never `Tunables`/`TUNABLE_DEFAULTS`, and is absent from `QUIVER_CONFIG_KEYS`; the settings lint reports `quiver.docToMd.words` as unknown. The extension schema, CLI parser, `--help`, and generated skill derive from the descriptor as they do for every other option. The `USAGE` one-liner in `bin/pi-quiver.ts` gains `[--words]`.

Descriptor `help` (tool parameter description and `--help` line): `Write word positions: <stem>.words.json beside the Markdown lists every text-layer word of each selected page with its bbox (PDF points, top-left origin, display orientation; image inputs in source pixels) and the words inline OCR recognized, tagged source "text" or "ocr"; under --ocr-mode all the OCR words go to ocr/<stem>-pNNN.words.json beside each sidecar. Never triggers OCR. PDF and image inputs only.`

`words` is a geometry export. It never starts OCR, changes page selection, or alters the Markdown, page stats, or OCR summary. `--words` with `--info` is a `UsageError`, joining the existing `--info cannot be combined with --pages, --output-dir, --overwrite, --page-images or --ocr-mode all` list (message and options test updated).

### 2. Main words file: `<stem>.words.json`

Lives next to `<stem>.pages.json`, with the same stem (so a collision-renamed run writes `<stem>-2.words.json`). The child writes the complete document under the bundle's staging dir (`<stagingDir>/words.json`, Design 3) and the result JSON carries only `"words": true`; the payload never travels over the capped child stdout, so a large word list cannot trip `maxOutputBytes` or push a PDF onto the fallback tier. `publishWords(b)` in `lib/doc-to-md-bundle.ts` renames the staged file to `b.wordsPath` before `commitBundle` (a rename within the bundle root is atomic; no partial file is ever visible). A failed rename leaves `wordsPath` null, removes any target, and is reported on the handle (Errors); `overwrite: true` cleanup and `abortBundle` remove `b.wordsPath` alongside `b.pageStatsPath`. Shape:

```json
{
  "unit": "pt",
  "pages": [
    { "page": 1, "width": 612.0, "height": 792.0, "rotation": 0,
      "words": [ { "text": "T2", "bbox": [412.3, 118.0, 428.9, 129.5], "source": "text" } ] }
  ]
}
```

- `unit` is `"pt"` for PDF input, `"px"` for image input (one input, one unit).
- `pages[]` carries one entry per selected page that has geometry (Design 4 names the one omission), in document order, keyed by the 1-based document page number - the same numbering as `<stem>.pages.json` and `pages/<stem>-pNNN`.
- `width`/`height` are the display-oriented page size (`page.rect` after rotation; for images the pixel size). `rotation` is the page's `/Rotate` value captured before conversion, informational.
- `words[]` is PyMuPDF's whitespace-delimited token list in its returned order; `bbox` is `[x0, y0, x1, y1]` in display space, rounded to one decimal; `source` is `"ocr"` only for a word that this run's inline OCR added (Design 3), `"text"` for every other word - including words of an input PDF that already carried an OCR layer (its spans keep the `GlyphLessFont` name, but they are text-layer content for this conversion). No normalization, dedupe, or line/block grouping; the tuple's `block`/`line`/`word` indexes are dropped.

The words describe exactly what the Markdown contains: native words, plus the words the `textless` path's inline OCR added to the page in this run. Under `ocrMode: all` the main pass runs with OCR off, so the main file holds native words only; the OCR words live beside the sidecars (Design 6).

### 3. Extraction in the Python children (`scripts/doc_to_md.py`)

Words are read in the child that already holds the page; no page is re-opened, re-rendered, or re-recognized for them.

- **`pdf-primary`**: per selected page, record `rotation = page.rotation` before `primary_page_markdown`. Afterwards, on a page where this run's inline OCR ran (the page is in `info["pages"]` or `info["noText"]`), build one `tp = page.get_textpage()` and take tokens and bboxes from `page.get_text("words", textpage=tp)` and the per-line fonts from `page.get_text("dict", textpage=tp)`; the shared textpage keeps `block`/`line` indexes aligned (the default `dict` call includes image blocks and `words` does not, so their numbering diverges on any page with a picture - `scan.pdf` page 1 included). A word whose line's spans are all `GlyphLessFont` is `ocr`, every other word `text`. On a page where no inline OCR ran, `page.get_text("words")` alone suffices and every word is `text`. Coordinates are display space already (pymupdf4llm removed the rotation); the child still multiplies by `page.rotation_matrix`, which is the identity here, so one code path serves both tiers. A page that pymupdf4llm failed on (already in `failedPages`) gets no words entry.
- **`pdf-fallback`**: per selected page, `page.get_text("words")` mapped through `page.rotation_matrix`; every word is `source: "text"` (this tier never OCRs). When `o["ocr"]` is true, a page whose text layer is empty (the child's own char count, the same test it uses for `textless`) is a requested-OCR-did-not-run page and gets no entry (Design 4).
- **`image`**: when `o["words"]` is true the child opens the `Pixmap` for `w_px`/`h_px` regardless of OCR status (today it does so only inside the OCR-ready branch). With OCR ran, the one-page PDF the image is converted into is the page: words are read as in `pdf-primary` inside the `with pymupdf.open(...) as pdf` block (the document closes when it exits), then scaled by `w_px / r.width` and `h_px / r.height` to source pixels; `width`/`height` are `w_px`/`h_px`, `rotation` 0. Without `--ocr` the single entry is `"words": []` with the pixel size.

When `o["words"]` is true, each of these three modes writes the complete document of Design 2 to `<stagingDir>/words.json` and sets `"words": true` in its result JSON; per-page extraction errors go to `"wordsErrors": { "<page>": "<ExceptionType>: <message>" }`, never to `notes` (child notes become `Notes:` lines in the committed Markdown). `lib/doc-to-md-core.ts` passes `words` in the child options for these modes, calls `publishWords(b)` when the result says `words: true`, and carries `wordsErrors` into the details.

### 4. The one omission: requested OCR that did not run

A page whose OCR was requested by the `textless` path and did not succeed (Tesseract unavailable, OCR exception, budget stop) has no entry in `pages[]`: an empty list would read as "this page has no words", which is false for a scanned page. The consumer finds the page in the `OCR:` summary's `unavailable`/`ocrFailed`/`budgetStopped` buckets. Every other selected page is present, including:

- a textless page with `--words` and no `--ocr`: `"words": []` (user decision - the `OCR:` line and `Page-Stats:` already name thin pages; no extra handle note);
- a `noText` page (inline OCR ran and recognized nothing): present with `"words": []`;
- a text-bearing page under `--ocr` (the `textless` policy skips OCR on it): native words only, pictures unrecognized;
- a page the fallback tier served with `--ocr` requested: native words; the tier's OCR status is `unavailable` for the whole run, and a textless page there is omitted per the rule above.

Under `ocrMode: all` the main pass requests no OCR, so the main file applies no omission: every selected page is present with its native words.

### 5. Image inputs

`mode_image` is the main-child path for `.png .jpg .jpeg .tif .tiff .bmp .gif`. `unit` is `"px"`, the entry's `width`/`height` are the source pixel size, and bboxes are in source pixels (Design 3). An image OCR that was `skipped` (too small), `unavailable`, or `ocrFailed` is a requested OCR that did not run: `pages` is `[]` and the file still exists. When the image is copied instead of converted (`engine: "copy"` - no Python backend, or the image child failed) there is no page and no pixel size: `wordsPath` is null and the handle says `Words: none - image copied without conversion (<reason>)`; the copied-image Markdown is unchanged.

### 6. Forced-OCR words: `ocr/<stem>-pNNN.words.json`

In `mode_ocr_pages`, when `o["words"]` is true, after `tp = page.get_textpage_ocr(full=True, ...)` the child calls `page.get_text("words", textpage=tp)`, maps each bbox through `page.rotation_matrix`, and writes `<stagingDir>/pNNN/<stem>-pNNN.words.json` beside the sidecar `.md`, before `mark_done`:

```json
{ "page": 2, "unit": "pt", "width": 612.0, "height": 792.0, "rotation": 0,
  "words": [ { "text": "3", "bbox": [72.0, 61.0, 78.5, 72.1], "source": "ocr" } ] }
```

Every word is `source: "ocr"` - this is the recognizer's view of the whole page, and it may repeat native words (the `3` above is also in the main file). A `noText` page writes a words file with `"words": []` beside its header-only sidecar. A recognition failure (`.failed`) removes both files. A words-only failure (extraction or write raised after the sidecar `.md` was written) keeps the sidecar and the page's OCR outcome unchanged: the words file is removed, the page is recorded in the child result's `wordsErrors`, and `.done` is still written - OCR results never change because geometry was requested.

`ownedOcrPattern(stem)` matches `<stem>-pNNN.md` and `<stem>-pNNN.words.json`, so `--overwrite` removes an earlier run's words sidecars even when the new run has no `--words` or fewer pages. `publishSidecars` moves the `.words.json` together with the `.md` out of each `.done` dir and adds both to `ocrManifest`, so `abortBundle` removes published words files too; a dir without `.done` is dropped as today. When the child was killed, `recoverOcrPages` already classifies staged `.done` pages and `publishSidecars` publishes them - both files ride along. `OcrInfo` gains `wordSidecars: Record<number, string>` (page -> absolute path), derived from what `publishSidecars` moved in this run, a sibling of `sidecars`; the `sidecars` shape is unchanged.

Consumers who want both views overlay `<stem>.words.json` and the sidecar words by page number and prefer `source: "text"` where boxes overlap; the converter does not dedupe (the #26 "no deduplication" rule applies to words as to text).

### 7. Reporting

`DocToMdDetails`/`HandleData` gain `wordsPath: string | null` and `wordsReason: string | null`. The handle line:

- `Words: <absolute path>` when the file was written;
- `Words: none - word positions apply to PDF and image inputs only (<type>)` for DOCX, DOC, PPTX, XLSX/XLSM/XLS, email, HTML;
- `Words: none - unpdf tier has no page geometry` when conversion reached the no-Python tier;
- `Words: none - image copied without conversion (<reason>)` on the image copy route (Design 5);
- `Words: write failed - <reason>` when publishing the staged file threw (Errors);
- a trailing ` (extraction failed for pages <list>: <first message>)` on the `Words: <path>` line when `wordsErrors` is non-empty; on an `all` run the same clause lists forced-OCR pages whose words file failed.

`Words:` always names the main artifact; forced-OCR geometry is named only by `ocr.wordSidecars`. No line without `--words`. The CLI `--json` gains `wordsPath` (null without `--words`), `wordsErrors`, and `ocr.wordSidecars`.

### 8. Help, skill, and bundle layout block

A `BUNDLE_LAYOUT` constant in `lib/doc-to-md-options.ts`, sibling of `USAGE_PATTERNS`, lists every artifact the bundle can contain - one row each: path pattern, what turns it on, what it holds, and the handle line / JSON key that names it:

| Artifact | Trigger | Content | Named by |
|---|---|---|---|
| `<stem>.md` | always | the Markdown | `Saved-To:` / `savedTo` |
| `images/` | embedded or extracted figures | image files linked from the Markdown | `Images-Dir:` / `imagesDir` |
| `pages/<stem>-pNNN.<fmt>` | `--page-images` | page renders at `--image-dpi` | `Pages-Dir:` / `pagesDir` |
| `sheets/` | Excel input | one CSV per non-empty worksheet | `Sheets-Dir:` / `sheetsDir` |
| `attachments/` | email input | saved attachments | Markdown attachment list |
| `<stem>.pages.json` | Python PDF tiers (PDF, PPTX, DOC, DOCX via LibreOffice; not unpdf) | per-page chars, image count, image coverage | `Page-Stats:` / `pageStatsPath` |
| `<stem>.words.json` | `--words` | per-page word boxes, `source` text/ocr | `Words:` / `wordsPath` |
| `ocr/<stem>-pNNN.md` | `--ocr --ocr-mode all` | recognized text of a forced page | `OCR-Dir:` / `ocr.sidecars` |
| `ocr/<stem>-pNNN.words.json` | `--ocr --ocr-mode all --words` | word boxes of that OCR | `ocr.wordSidecars` |

`renderHelp()` prints it under a `Bundle layout` heading next to the `usagePatterns(...)` block, and `scripts/gen-skill.mjs` renders the same constant into `skills/doc-to-md/SKILL.md`, so help and skill share one source (the pi tool description in `extensions/doc_to_md.ts` is a hand-written literal and is unchanged). The `## Bundle and handle` section of `doc/doc-to-md.md` cites the same rows (hand-written there; the drift test covers only the generated skill). The "Named by" wording for existing lines matches `lib/doc-to-md-handle.ts` (`Images-Dir:`, `Sheets-Dir:`, `Pages-Dir:`, `Page-Stats:`, `OCR-Dir:`); `attachments/` has no handle line today and the row says so.

## Errors and edge cases

- **Word extraction never fails a conversion or changes any other output.** If `get_text` (or the image pixel-size read) raises on a page in a main-child mode, the page gets no entry and the page is recorded in the child result's `wordsErrors`; Markdown bytes, `notes`, page stats, and OCR buckets are identical to the run without `--words`. In `mode_ocr_pages` a words-only failure keeps the sidecar and the page's OCR outcome (Design 6).
- **Words publication fails** (staged file missing or rename threw): the conversion succeeds, `wordsPath` is null, any partial target is removed, and the handle says `Words: write failed - <reason>`. Publication runs before `commitBundle` and is caught, not thrown, so a committed Markdown normally has its words file; this nonfatal failure is the one documented exception.
- **Unsupported input type**: not an error; `Words: none - word positions apply to PDF and image inputs only (<type>)`, `wordsPath` null, no file. PPTX and DOC are excluded by the ticket's product contract even though they pass through the PDF ladder.
- **`--ocr-mode all` validation** (`--ocr` present, explicit `--pages` for PDF/PPTX/DOC) is unchanged and runs before `words` is considered; with `words` and `all` on a PPTX or DOC, the sidecars get no words files and the main `Words:` line reports the unsupported type.
- **Empty page** (no spans, no OCR requested): `"words": []`, present.
- **Page selection**: only selected pages appear, keyed by document page number; `pages: []` when every selected page was omitted (Design 4).
- **Rotated pages**: display coordinates on every path. The `all` child renders a rotated page unrotated, so Tesseract reads it sideways and may return garbage text (observed: `Oo`, `fo}` for `Hello OCR` on a `/Rotate 90` scan); the bboxes it emits are still mapped correctly. This is a #26 limitation filed separately, not fixed here.
- **Mixed main/sidecar duplicates** under `all`: not deduped; stated as a consumer rule (Design 6).
- **Collision and overwrite**: `<stem>.words.json` follows the stem (`<stem>-2.words.json` on collision); removed by `overwrite: true` and by abort together with `<stem>.pages.json`. Re-running an `all` conversion follows the existing rules: a fresh stem on collision, or `--overwrite` removing every owned `ocr/<stem>-pNNN.*` file (Design 6); no cross-run sidecar reuse exists.
- **Payload size**: the words document is staged on disk, never on child stdout, so a page-heavy PDF with `--words` fits `maxOutputBytes` exactly as it does without the flag and never changes tier or OCR outcome.
- **Ligatures, hyphenation, odd tokens**: PyMuPDF's tokens as returned; no normalization.
