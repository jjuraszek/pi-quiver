A proposal adds a second settings-reading path beside the existing resolver, the helper that reads settings.json and chooses the value for each call. The proposal assumes settings are read once at startup and says a second reader is needed to notice edits during a session. That assumption is wrong: the existing resolver re-reads settings.json on every call. For example, changing the display setting from compact to expanded is already picked up by the next call without restarting. The proposal calls both readers on every lookup, so it would turn one settings-file read into two while returning the same updated value. There is only one caller for the proposed new helper. The decision is whether to add the second path or keep the existing resolver. Explain and judge the proposal.
